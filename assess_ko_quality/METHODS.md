# Methods reference

Every method, threshold and weight the pipeline uses, and where each number came from.
`README.md` explains *why*; this file is the *what*, precisely enough to reimplement.

Nothing here was chosen by hand. Each value is either fitted against human review,
derived from the corpus, or calibrated on a labelled set — the provenance column says
which, and the artifact named holds the current value. **Code is not the source of
truth for any of these numbers**: the artifacts are, and they are regenerated by the
commands in the last section.

---

## 1. Stage 0 — Domain gate

| Property | Value |
|---|---|
| Method | Logistic regression on sentence embeddings |
| Embedding model | `all-mpnet-base-v2`, first 2,000 characters of content (or description) |
| Positive class | Real KOs from the export |
| Negative class | Off-domain documents (Wikipedia, five languages) |
| Artifact | `validation/gate_validation/domain_gate_model.pkl` |
| Validation set | `validation/gate_validation/gate_validation_set.json` (678 items) |
| Performance | AUC 1.000 (5-fold CV, 400 in / 130 out) |

### Thresholds

| Band | Condition | Effect |
|---|---|---|
| accept | P ≥ 0.40 | Scored normally |
| review | 0.20 ≤ P < 0.40 | Routed to a person |
| reject | P < 0.20 | Not scored; `quality_score` is null |

At `accept`: 100% of real KOs retained in all 14 languages tested, 94.6% of off-domain
caught. The threshold is **not** raised further because a language gap opens above 0.60
— at 0.70, German retention falls to 83% and Greek to 33%.

### What was rejected, and why

| Method | AUC | Verdict |
|---|---|---|
| Cosine to the mean of 96,691 AGROVOC/NALT anchors | 0.647 | The previous Domain pillar. Scored gibberish (0.069) the same as a crop-rotation guide (0.071). |
| Mean of the top-10 anchor similarities | 0.768 | Better, still unusable: at 99% KO retention it caught 16% of off-domain. |
| Logistic regression on embeddings | 1.000 | **In use.** |

## 2. Stage 1 — Compliance

Not part of the score. As a scored component, completeness correlated with reviewer
judgement at **−0.217** (p = 0.039) — significant, and the wrong direction.

| Property | Value |
|---|---|
| Artifact | `validation/compliance_profile.json` |
| Obligations | 18, learned from 10,468 records |
| Rule | A field populated in ≥ 95% of records, **and** classified as contributor-supplied |
| Field classification | LLM, into contributor / system / derived |
| Staleness cut-off | 2016 — the 5th percentile of corpus completion years |
| Vocabularies | Every `data_model.*.json` found in `data_model_v2/` |

Only contributor fields become obligations. `title_llm`, `ko_content_flat_vision` and
`locations_flat` are populated nearly everywhere but are *derived* — failing a KO
because our own enrichment did not run would be nonsense.

Each check returns pass, fail, or **not evaluable** (no vocabulary present locally, or
no profile). Not-evaluable never counts as a failure.

## 3. Stage 2 — The quality score

### The arithmetic

```
score = 100 × clamp( intercept + Σ wᵢ · percentile(featureᵢ) , 0, 1 )
```

`percentile(x)` is the position of `x` in `reference_quantiles[feature]` — 101 points
stored in the model artifact. See the provenance note below — they come from the
corpus for the text features, from the fitting sample for the judge.

### Weights — model `with_judge` (CV ρ 0.610)

| Feature | Weight | Share |
|---|---|---|
| intercept | +0.0316 | — |
| `log(1 + content_tokens)` | +0.2061 | 20% |
| `log(1 + MTLD)` | +0.2007 | 20% |
| `judge_overall` | +0.6130 | 60% |

### Weights — model `no_judge` (CV ρ 0.535)

| Feature | Weight | Share |
|---|---|---|
| intercept | +0.1024 | — |
| `log(1 + content_tokens)` | +0.3280 | 51% |
| `log(1 + MTLD)` | +0.3198 | 49% |

Selected automatically: `with_judge` when a judge verdict is present, `no_judge`
otherwise, reported in `quality_score_model`.

Both models are rescaled to the range they can actually reach, so each spans 0–100.
The ridge fit was never constrained to span 0–1 — raw outputs covered 0.032–1.051
(`with_judge`) and 0.102–0.750 (`no_judge`), which meant `no_judge` could never exceed
75 and a 70 from one model did not mean a 70 from the other. Since every feature is a
percentile in [0, 1], the reachable interval is the intercept plus the positive weights
at the top and the negative ones at the bottom; the score is normalised against it.
`quality_score_raw` and `quality_score_range` are emitted alongside.

**Ties take the mid-rank.** The weights were fitted on features ranked with pandas'
default, which averages tied ranks. Scoring originally took the lower edge of a tie
block, applying the weights to a different quantity than they were fitted to. It
mattered most for the judge, whose answers take only five distinct values and are
therefore almost all ties.

| Property | Value |
|---|---|
| Artifact | `validation/score_model.json` |
| Fitted against | `human_recommend_0_1` — the 2024 review consensus |
| Training sample | 91 KOs (the overlap of the review and the June-2026 export) |
| Reference distribution | The **corpus** (10,468 KOs) for both text features; the fitting sample for the judge |
| Estimator | Ridge, α selected by CV (0.316 with judge, 1.0 without) |
| Ceiling | 0.847 — inter-rater ρ 0.558, two-rater reliability 0.717 |

### The reviewed sample is not representative — and what was done about it

| | reviewed sample | corpus | |
|---|---|---|---|
| content length, median chars | 3,428 | 1,807 | p < 0.0001 |
| failed extractions (< 400 chars) | 12.0% | 35.8% | |
| English | 76.1% | 59.9% | p = 0.002 |
| Crop farming | 39% | 54% | |
| Forestry | 8.7% | 17.6% | |
| Economics | 37% | 21% | |
| Society | 33% | 19% | |

Content length is a score input, so this is not a footnote. Measured on the sample's own
percentile scale, the **median corpus KO sat at the 19th percentile** and 52.9% of the
corpus fell in the bottom quarter — every score on the platform would have been
depressed by the sample the model happened to be fitted on.

Reference quantiles for both text features are therefore taken from the corpus, not the
sample. Percentile transforms are monotone, so the ranking the model was validated on is
preserved: the two scorings agree at rho 0.997, and correlation with reviewers is 0.691
against 0.684. The judge's quantiles remain sample-based, because the corpus has not
been judged end to end.

**This does not fix the underlying problem.** The weights are still fitted on 91
unrepresentative KOs. Whether the relationship itself holds on short, non-English,
Forestry-heavy content is untested, and cannot be tested without review covering it.

### Judge bias audit

The judge carries 60% of the weight, so it was audited on the dimensions most likely to
carry bias (n = 91, cached judgements, both glm-5.2 and gpt-oss-120b):

| Check | Result |
|---|---|
| Rates non-English lower than humans do? | **No.** Judge−human gap is *smaller* for non-English (+0.07) than English (+0.21). |
| Agreement differs by language? | **Yes, favourably** — glm rho 0.78 on non-English against 0.50 on English. Same direction for gpt-oss. |
| Length bias? | **No.** rho(length, judge−human) = −0.09 and −0.10. |
| Penalises failed extractions more than humans? | **No.** Judge 0.09 against human 0.11 on broken KOs. |

The judge *is* uniformly more generous than reviewers (+0.07 to +0.25). That is a
constant offset, absorbed by the fitted intercept, not a bias between groups.

### Definitions

**`content_tokens`** — tokens in `ko_content_flat` after whitespace normalisation,
lowercasing, URL removal and punctuation stripping, keeping tokens of ≥ 2 characters.
Used **continuously**. Banding it into 0–5 bins destroyed 53% of its signal and
penalised the long documents reviewers preferred.

**`MTLD`** — Measure of Textual Lexical Diversity over stopword-stripped content.
Mean token span over which running type-token ratio stays above 0.72, averaged forward
and backward (McCarthy & Jarvis, 2010). Texts under 10 tokens return their own length.

Replaced the type-token ratio, which falls mechanically with length (ρ −0.93), scored
93.7% of the corpus 5/5, and correlated with reviewers at **−0.29**. MTLD scores
**+0.47**, and +0.30 after partialling out length.

**`judge_overall`** — an LLM's answer to the review form's final question, *"would you
recommend this KO to a general practitioner or intermediary"*, on 1–5, normalised
`(v − 1) / 4`.

### Model selection for the judge

Four families, same rubric, same 92 KOs:

| Model | ρ vs human | Time | Completion tokens |
|---|---|---|---|
| **glm-5.2** | **0.612** | 98s | 58,872 |
| gpt-oss-120b | 0.493 | 119s | 116,814 |
| mistral-medium-3.5-128b | 0.470 | 138s | 55,780 |
| qwen3.5-397b-a17b | 0.379 | 113s | 64,073 |

glm-5.2 agrees with the reviewer consensus more closely than two reviewers agree with
each other (0.558). The glm-vs-gpt-oss gap is **not statistically reliable** on n = 91:
bootstrap 95% CI [−0.000, +0.237], glm ahead in 97.5% of resamples.

**One judge, not a panel.** More judges make the score worse: one 0.638, two 0.620,
four 0.600 (CV, with the heuristics). The families correlate 0.61–0.71, so extras cost
parameters without adding information.

Evidence: `validation/runs/panel_<model>.json`.

### What the score does not include, and why

Measured against reviewer judgement on 91 KOs. Everything below was tested and dropped:

| Measurement | ρ | Disposition |
|---|---|---|
| Structural completeness | −0.217 | Moved to compliance — wrong direction as a score term |
| Structural noise | −0.148 | Diagnostics only |
| Semantic clarity | −0.137 | Diagnostics only |
| Semantic usefulness | −0.048 | Diagnostics only |
| Semantic consistency (Jaccard) | −0.009 | Diagnostics only |
| Domain term density | +0.030 | Replaced by the gate |
| Domain in title / keywords / consistency | −0.13 to −0.04 | Replaced by the gate |
| Functional embedding / RAG / keyword readiness | +0.08 to +0.17, n.s. | Reported, unvalidated |

The four-pillar total scored **0.174**. Given free choice of weights over the four
pillars, a ridge model scored **−0.170** out of sample — below chance. The problem was
never the 30/35/25/10 weighting.

### Not validated

`retrieval_readiness` is emitted with `retrieval_readiness_is_validated: false`. It has
never been checked against retrieval outcomes, and its length assumptions are suspect:
the index is chunk-per-doc, so a long document is not penalised by the retriever the
way these proxies assume. Validating it means joining against the ClickHouse search
logs.

## 4. Stage 3 — Diagnostics

Nothing here enters the score, and nothing is phrased as a fault — the measurements
involved do not predict reviewer judgement, so calling a KO "noisy" would assert more
than the evidence supports.

| Property | Value |
|---|---|
| Artifact | `validation/diagnostic_thresholds.json` |
| Method | Per-metric corpus percentiles; flag when a value falls in either tail |
| Tails | 1st and 99th percentile |
| Metrics kept | 57 of 90 |
| Excluded | Fewer than 12 distinct values (a percentile on a 0–5 score is a tie, not a tail); raw size metrics |
| Expected by chance | ~1.14 flags per KO — reported as `diagnostics_expected_by_chance` |

The chance rate travels with the count deliberately. An earlier version used 5th/95th
percentiles over 85 metrics and flagged exactly 8 metrics on *every* KO — arithmetic,
not diagnosis.

Two things *are* reported as problems, because they are not opinions about quality:
extraction failure (< 80 content tokens) and failed compliance obligations.

Plain-language notes come from the judge's per-question justifications.

## 5. LLM configuration

Documented in [`../USING_LLMS.md`](../USING_LLMS.md). `core/llm.py` adapts
`semantic_vs_search/llm_client.py` (disk caching, retries, `reasoning_effort` handling,
token accounting) and adds runtime model discovery.

| Property | Value |
|---|---|
| Provider | Scaleway, OpenAI-compatible |
| Credentials | `farm_assistant_um/.env` first, then this repo's `.env` |
| Model selection | Preference expression resolved against `GET /v1/models` |
| Default | `KOQ_LLM_MODEL`, else `qwen3.5,gpt-oss,mistral-medium,glm` |
| Judge | `--judge-model glm` |
| Cache | `.cache/llm`, keyed on a SHA-256 of the whole request |

`reasoning_effort=none` matters: without it qwen3.5 spent 1,640s on work that takes
113s with it, and can return empty content that looks like a failed row rather than a
wrong answer.

## 6. Regenerating every number in this file

```bash
cd assess_ko_quality

python pipeline.py --input ../input/<export>.json --learn   # compliance + diagnostics
python -m validation.validate_metrics                       # score weights, correlations
python -m stages.gate --calibrate                           # gate model and thresholds
```

Each writes its artifact under `validation/`. After refitting, update the weight tables
above from `validation/score_model.json` — or read them there, which is authoritative.

## 7. Limitations

- **91 training KOs.** Small, and the features were chosen after examining that same
  sample. Cross-validation protects the weights, not the choice of inputs. The score is
  provisional until it holds on a held-out review batch.
- **The judge carries 60% of the weight.** The number is substantially an LLM verdict
  anchored by two text statistics, with the cost and reproducibility that implies.
- **One corpus, one rubric, one point in time.** The 2024 review covered 101 KOs; 92
  survive into the current export.
- **A noisy criterion.** Reviewers agree with each other at 0.558 on the overall
  recommendation, and at only 0.14–0.34 on the five other dimensions — which is why
  only the overall recommendation is used as a target.
- **Factual accuracy is not measured.** Nothing here checks whether a KO's advice is
  correct.
